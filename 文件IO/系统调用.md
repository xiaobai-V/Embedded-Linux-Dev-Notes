## 系统调用

### 什么是系统调用

系统调用（System Call）是用户程序请求操作系统内核服务的接口。用户程序运行在**用户态**（受限），系统调用是进入**内核态**的唯一合法途径。

```
用户程序  --(系统调用)-->  内核
  |                          |
  | open/read/write/...      | 实际操作硬件/文件系统/进程
  |<--(返回结果)------------ |
```

Linux 系统调用的调用流程：用户程序调用封装函数（如 glibc 的 `open()`） → 触发软中断/`syscall` 指令 → 切换到内核态 → 内核执行对应的服务例程 → 返回结果到用户态。

### 系统调用与标准C库的区别

| 方面 | 系统调用 | 标准C库 (stdio) |
|------|---------|---------------|
| 层级 | 内核接口，直接与内核交互 | 用户态封装，内部可能调用系统调用 |
| 缓冲 | 无缓冲，每次调用都陷入内核 | 有缓冲区（如 stdio 的 buffer），减少系统调用次数 |
| 可移植性 | Linux/POSIX 特有 | 跨平台（C 标准） |
| 文件操作对象 | 文件描述符 (int fd) | FILE* 指针（流） |
| 性能 | 每次调用涉及上下文切换，开销较大 | 缓冲减少系统调用次数，适合小块数据 |
| 示例 | open / read / write / close | fopen / fread / fwrite / fclose |

> 选择建议：需要精细控制（如指定权限、非阻塞IO）时用系统调用；普通文件读写用标准C库更方便。

### 常用文件IO系统调用速查

#### open — 打开或创建文件

```c
#include <fcntl.h>
int open(const char *path, int oflag, ... /* mode_t mode */);
// 成功返回文件描述符，失败返回 -1
```

常用 oflag：

| 标志 | 含义 |
|------|------|
| `O_RDONLY` | 只读 |
| `O_WRONLY` | 只写 |
| `O_RDWR` | 读写 |
| `O_CREAT` | 不存在则创建（需提供 mode 参数） |
| `O_TRUNC` | 截断为 0 长度 |
| `O_APPEND` | 追加写入 |

> 示例：见 `system_call_test.c` 中 O_RDONLY 和 O_CREAT\|O_WRONLY\|O_TRUNC 两种模式

#### read — 读取文件

```c
#include <unistd.h>
ssize_t read(int fd, void *buf, size_t nbytes);
// 成功返回实际读取字节数，EOF 返回 0，失败返回 -1
```

- 返回值可能小于 nbytes（部分读），不一定是错误
- 返回 0 表示到达文件末尾

#### write — 写出数据

```c
#include <unistd.h>
ssize_t write(int fd, const void *buf, size_t n);
// 成功返回实际写出字节数，失败返回 -1
```

- 可能只写出部分数据（部分写），需要循环保证全部写出

#### close — 关闭文件描述符

```c
#include <unistd.h>
int close(int fd);
// 成功返回 0，失败返回 -1
```

- 进程终止时内核自动关闭所有打开的 fd

#### lseek — 调整文件偏移量

```c
#include <unistd.h>
off_t lseek(int fd, off_t offset, int whence);
// 成功返回新的偏移量，失败返回 (off_t)-1
```

| whence | 含义 |
|--------|------|
| `SEEK_SET` | 文件开头 |
| `SEEK_CUR` | 当前位置 |
| `SEEK_END` | 文件末尾 |

- 可以越过文件末尾，后续写入会形成**文件空洞**
- 不适用于管道、套接字、FIFO

> 示例：见 `system_call_test.c` 中 lseek 回到文件开头再读取

#### dup / dup2 — 复制文件描述符

```c
#include <unistd.h>
int dup(int fd);          // 返回最小可用 fd
int dup2(int fd, int fd2); // 复制到指定 fd2
```

- 复制后的 fd 与原 fd **共享文件表项**（共享偏移量）
- dup2 是原子操作，不会出现 close 和 dup 之间的竞争

> 示例：见 `system_call_test.c` 中 dup 示例

#### access — 检查文件访问权限

```c
#include <unistd.h>
int access(const char *name, int type);
// 有权限返回 0，无权限返回 -1
```

| type | 含义 |
|------|------|
| `F_OK` | 文件是否存在 |
| `R_OK` | 可读 |
| `W_OK` | 可写 |
| `X_OK` | 可执行 |

- 检查的是**实际用户ID**（real UID）的权限，不是有效用户ID

> 示例：见 `system_call_test.c` 中 access 示例

#### fcntl — 文件描述符控制（进阶）

```c
#include <fcntl.h>
int fcntl(int fd, int cmd, ... /* arg */);
```

常用 cmd：

| cmd | 功能 |
|-----|------|
| `F_DUPFD` | 复制 fd（类似 dup，但可指定最小值） |
| `F_GETFD` / `F_SETFD` | 获取/设置文件描述符标志（如 FD_CLOEXEC） |
| `F_GETFL` / `F_SETFL` | 获取/设置文件状态标志（如 O_APPEND、O_NONBLOCK） |

### errno 错误处理

系统调用失败时通常返回 -1，并设置全局变量 `errno` 指示具体错误原因。

```c
#include <errno.h>  // errno 定义
#include <stdio.h>  // perror
#include <string.h> // strerror

// 标准错误处理模式：
int fd = open("file.txt", O_RDONLY);
if (fd == -1) {
    perror("open");  // 输出: open: No such file or directory
    // 或手动格式化：
    // printf("error: %s\n", strerror(errno));
    exit(EXIT_FAILURE);
}
```

**注意**：`errno` 在系统调用成功时**不会**被清零。必须在函数返回 -1 之后再读取。

#### perror 与 strerror

| 函数 | 头文件 | 功能 |
|------|--------|------|
| `perror(const char *s)` | `<stdio.h>` | 输出 `s: <错误描述>` 到 stderr |
| `strerror(int errnum)` | `<string.h>` | 返回错误码对应的描述字符串 |

#### 常见 errno 值

| errno | 含义 |
|-------|------|
| `ENOENT` | 文件不存在 |
| `EACCES` | 权限不足 |
| `EEXIST` | 文件已存在（O_CREAT + O_EXCL 时） |
| `EISDIR` | 是目录 |
| `ENOTDIR` | 不是目录 |
| `EMFILE` | 进程打开文件数达到上限 |
| `ENFILE` | 系统级打开文件数达到上限 |
| `EINVAL` | 无效参数 |
| `ESPIPE` | 不支持 seek（管道/套接字） |
