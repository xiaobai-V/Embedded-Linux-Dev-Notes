# Linux 进程树

## 一、进程树概述

Linux 系统中所有进程组织成一棵树形结构，根节点是 PID 为 1 的 init 进程（现代系统为 systemd）。每个进程都有一个唯一的 PID（Process ID）和一个 PPID（Parent Process ID），通过父子关系形成树状层次。

```
systemd (PID=1)
├── sshd (PID=100)
│   └── bash (PID=200)
│       └── vim (PID=300)
├── cron (PID=101)
└── nginx (PID=102)
    ├── worker (PID=103)
    └── worker (PID=104)
```

**核心概念：**

- **PID**：进程唯一标识，由内核分配
- **PPID**：父进程的 PID
- **fork()**：创建子进程，子进程是父进程的副本
- **execve()**：替换进程映像，执行新程序
- **wait/waitpid()**：父进程等待子进程结束，回收资源
- **孤儿进程**：父进程先于子进程结束，子进程被 init 领养
- **僵尸进程**：子进程已结束但父进程未调用 wait 回收

## 二、进程创建 — fork()

`fork()` 创建一个与父进程几乎完全相同的子进程（代码段、数据段、堆、栈、文件描述符表等都会复制）。父子进程从 fork 返回点开始各自独立执行。

```c
#include <unistd.h>
pid_t fork(void);
```

**返回值：**
- 父进程中返回子进程的 PID（> 0）
- 子进程中返回 0
- 失败返回 -1

**典型用法：通过返回值区分父子进程的执行路径：**

```c
pid_t pid = fork();
if (pid == -1) {
    perror("fork");
} else if (pid == 0) {
    // 子进程逻辑
} else {
    // 父进程逻辑
}
```

## 三、程序替换 — execve()

`execve()` 用新程序替换当前进程的代码段、数据段、堆和栈，但 PID 不变。通常与 fork 配合使用：fork 创建子进程，execve 让子进程执行新程序。

```c
#include <unistd.h>
int execve(const char *pathname, char *const argv[], char *const envp[]);
```

**参数说明：**

| 参数 | 含义 |
|------|------|
| `pathname` | 要执行的程序路径 |
| `argv[]` | 参数数组，`argv[0]` 为程序名，末尾必须为 `NULL` |
| `envp[]` | 环境变量数组，格式为 `key=value`，末尾必须为 `NULL` |

**返回值：** 成功时不返回（进程映像已被替换），失败返回 -1。

> **注意：** execve 成功后，原程序中 execve 之后的代码不会执行。

## 四、进程树构建示例

### 4.1 fork + execve 组合（进程树构建的核心模式）

本项目的 `pstree_test.c` 演示了典型的 fork + execve 模式：

```
 pstree_test 进程                erlou 进程
 (老学员，一楼)                  (二楼)
       |
       |--- fork() ---|
       |              |
       |         子进程(新学员)
       |              |
       |         execve()
       |              |
       |         变成 erlou 进程
       |         (新学员上二楼)
       |
  fgetc(stdin)
  (老学员在一楼等待)
```

**对应代码流程（`pstree_test.c`）：**

1. 父进程（老学员）打印自己信息
2. `fork()` 创建子进程（新学员）
3. 子进程调用 `execve()` 跳转到 `erlou` 程序（上二楼）
4. 父进程通过 `fgetc(stdin)` 挂起，等待用户输入

**观察进程树：** 在父进程挂起期间，另开终端执行 `ps -ef` 或 `pstree` 可以看到父子关系。

### 4.2 进程等待 — waitpid()

`waitpid_test.c` 演示了父进程等待子进程完成：

```c
pid_t pid = fork();
if (pid == 0) {
    // 子进程执行 ping
    execve("/usr/bin/ping", args, envs);
} else {
    // 父进程等待子进程结束
    waitpid(pid, &status, 0);
}
```

**waitpid 函数原型：**

```c
#include <sys/wait.h>
pid_t waitpid(pid_t pid, int *status, int options);
```

| 参数 | 含义 |
|------|------|
| `pid` | 指定等待的子进程 PID（-1 表示等待任意子进程） |
| `status` | 子进程退出状态 |
| `options` | 0 表示阻塞等待，`WNOHANG` 表示非阻塞 |

## 五、孤儿进程

当父进程先于子进程结束，子进程就成为**孤儿进程**。Linux 内核会将孤儿进程的父进程重新设置为 init（PID=1），由 init 负责回收。

**`orphan_process_test.c` 演示：**

```
 orphan_process_test 进程         erlou_block 进程
 (老学员)                         (二楼学员)
       |
       |--- fork() ---|
       |              |
       |         子进程
       |         execve()
       |              |
       |         erlou_block
       |         (sleep 100秒)
       |
  父进程立即退出
  (老学员提前离开)
       ↓
  子进程成为孤儿
  PPID 变为 1（被 init 领养）
```

**验证方法：** 程序运行后，在另一个终端执行 `ps -ef | grep erlou_block`，可以看到该进程的 PPID 已经变成 1。

## 六、错误处理 — errno 与 perror

系统调用失败时，内核会设置全局变量 `errno` 来指示具体的错误原因。`perror()` 可以将 errno 对应的错误描述输出到 stderr。

```c
#include <errno.h>    // errno 定义
#include <stdio.h>    // perror 定义

void perror(const char *s);  // 输出格式: "s: 错误描述\n"
```

**示例：**

```c
// perror_test.c
fopen("none.txt", "r");     // 文件不存在，失败
perror("open");              // 输出: open: No such file or directory

// errno_test.c
fopen("/opt", "a+");         // /opt 是目录，无法以 a+ 打开
printf("errno: %d\n", errno); // 输出具体错误号
perror("文件打开出现问题");    // 输出: 文件打开出现问题: Is a directory
```

## 七、进程树相关常用命令

```bash
# 查看进程树
pstree

# 以 PID 显示
pstree -p

# 查看指定进程的子树
pstree -p <PID>

# 查看所有进程信息
ps -ef

# 查看进程的 PPID
ps -o pid,ppid,cmd

# 实时监控进程
top
htop
```
